# Тестирование CSPRNG

## Автоматические проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Набор проверяет генерацию 1000 уникальных 128-битных ключей, среднюю долю
единичных битов в диапазоне 45–55 %, обработку сбоя ОС, автоматическую
генерацию ключа в CLI и полный цикл шифрования. Также выполняются тесты
режимов, SHA-256, SHA3-256, CLI `dgst` и совместимости с OpenSSL.

## Переносимая батарея SP 800-22

Установить отдельные статистические зависимости:

```powershell
python -m pip install -e ".[nist]"
```

Создать последовательность длиной 1 100 000 бит и запустить все 15 тестов:

```powershell
python scripts/generate_nist_data.py --size 137500 --output nist_test_data.bin
python scripts/run_nist_tests.py nist_test_data.bin --report nist_results.txt
```

Runner использует `nistrng 1.2.3`, переносимую Python-реализацию NIST
SP 800-22 Rev. 1a. Каждый тест получает отдельную копию массива: это обход
дефекта библиотеки, при котором тест ранга изменяет данные последующих тестов.
Успех runner означает, что доступны все 15 тестов и прошло не менее 80 %.

### Результат контрольного запуска

- дата: 28 сентября 2026 года;
- источник: `os.urandom()` через `generate_random_bytes`;
- объём: 137 500 байт, или 1 100 000 бит;
- выполнено: 15 из 15 тестов;
- пройдено: 12 из 15;
- не пройдены: Overlapping Template Matching, Linear Complexity и Random Excursion;
- остальные p-value выше или равны 0,01.

Результат удовлетворяет заданному критерию «большая часть тестов проходит».
Статистические тесты не доказывают криптографическую стойкость; безопасность
источника основана на системном CSPRNG, который предоставляет `os.urandom()`.

## Официальная C-версия NIST STS

1. Скачать `sts-2_1_2.zip` со страницы NIST:
   <https://csrc.nist.gov/projects/random-bit-generation/documentation-and-software>.
2. Собрать программу по приложенной инструкции в Linux/WSL с C-компилятором.
3. Создать файл из 100 последовательностей по 1 000 000 бит:

```powershell
python scripts/generate_nist_data.py --size 12500000 --output nist_test_data.bin
```

4. Запустить `assess` с длиной одной последовательности 1 000 000 бит:

```bash
./assess 1000000
```

5. Выбрать пользовательский файл, все тесты, параметры по умолчанию, одну
   сотню последовательностей и двоичный формат. Итог появится в
   `experiments/AlgorithmTesting/finalAnalysisReport.txt`.

### Результат фактического запуска

- дата: 28 сентября 2026 года;
- программа: официальная C-реализация NIST STS 2.1.2;
- среда: Ubuntu в WSL 2;
- источник: `os.urandom()` через `generate_random_bytes`;
- объём файла: 12 500 000 байт, или 100 000 000 бит;
- SHA-256 файла: `fb172040e5df4635056b20df50586300ad32e252b59b6088fb0204c15c83fe34`;
- число последовательностей: 100;
- длина последовательности: 1 000 000 бит;
- формат: двоичный;
- выбраны все 15 тестов и параметры по умолчанию;
- отметки о провале (`*`) в итоговом отчёте отсутствуют.

Для основных тестов минимальная допустимая доля составляла 96 из 100.
Фактические доли находились в диапазоне от 96/100 до 100/100. Для Random
Excursions и Random Excursions Variant тестируемыми оказались 57
последовательностей: фактический минимум 56/57 при допустимом минимуме 54/57.
Все значения проверки равномерности p-value превышают порог 0,0001.

Полный неизменённый отчёт программы сохранён в
[`nist_sts_final_report.txt`](nist_sts_final_report.txt).

Таким образом, набор данных, полученный через CSPRNG проекта, прошёл все
применённые критерии официальной батареи NIST STS. Статистический результат
не является доказательством криптографической стойкости и дополняет, но не
заменяет анализ безопасности системного источника `os.urandom()`.

## Проверка замечаний преподавателя к спринту 3

Дата проверки: 1 октября 2026 года. Версия: 0.4.1.

Фактические результаты:

- Windows: полный набор — 76 тестов за 25,568 с, `OK (skipped=1)`;
  75 выполнены успешно, проверка POSIX-прав пропущена на Windows.
- Ubuntu / WSL 2: набор безопасности — 21 тест за 0,833 с,
  `OK (skipped=2)`; 19 выполнены успешно, две проверки Windows ACL пропущены.
  Проверка POSIX-прав, пропущенная на Windows, здесь выполнена успешно.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m unittest tests.test_security -v
```

Проверки в `tests/test_security.py`:

- GCM: известные ответы для нулевого ключа/nonce, пустого сообщения и одного
  блока; сверка с PyCryptodome для пяти длин nonce, шести длин сообщений и
  трёх вариантов AAD; изменение каждого бита шифротекста и тега;
- неверные ключ, nonce и AAD, отказ до расшифрования;
- HMAC: вектор RFC 4231 и независимая сверка для пустого, обычного и длинного ключа;
- все 16 длин PKCS#7 и повреждение каждого байта дополнения;
- padding oracle: для CBC-HMAC изменения заголовка, IV, шифротекста и тега
  дают общую ошибку; CBC и unpad вообще не вызываются при неверном MAC;
- CTR: отдельные nonce/counter, сверка с эталоном, отказ при исчерпании счётчика,
  смена nonce между сегментами, защита от перестановки и усечения;
- контроль повтора nonce при неисправном источнике;
- ключевые файлы: создание, чтение, запрет перезаписи и ссылок, сохранность
  существующего ключа и выходного файла при отказе;
- Windows ACL: права только для владельца и отключённое наследование;
- Linux/WSL: права 0600, отказ чтения файла 0644 и символической ссылки;
- статистика: 65 536 байт CSPRNG с эмпирической энтропией распределения
  больше 7,95 бит/байт и 1000 уникальных 96-битных nonce.

Оценка энтропии Шеннона относится к частотам байтов в выборке и не доказывает
энтропию системного источника. Она дополняет ранее выполненную официальную
NIST STS. При постоянной выборке функция возвращает 0, при равномерной — 8.

Проверка padding выполняет фиксированные 16 итераций, но не даёт строгой
гарантии constant-time в Python. Тесты защиты от oracle относятся к
аутентифицированному CBC-HMAC. Старый CBC без MAC сохраняется для совместимости
и не должен предоставляться как доступный злоумышленнику сервис расшифрования.

GCM сверяется с независимой реализацией PyCryptodome: `openssl enc` не
поддерживает GCM. Потоковая обработка AAD большого размера из полного спринта 6
в этих дополнениях не реализована; весь шестой спринт завершённым не объявляется.
